## Pattern

- Two pointers, opposite ends template.
- Key: sort, fix one, two sum the rest, skip repeats.

## Clarify

- Unique by values, not by index?
- Any order for the triplets and inside them?
- n up to 3000, so O(n²) is fine, O(n³) is not.

## Brute force

O(n³), with a set to drop repeats.

```
for i in range(n):
    for j in range(i + 1, n):
        for k in range(j + 1, n):
            if nums[i] + nums[j] + nums[k] == 0:
                seen.add(sorted triplet)
```

## Bottleneck

- Once `nums[i]` is fixed, the inner two loops are a pair sum to `-nums[i]`.
- Sort once, and that pair sum is Two Sum II in O(n).

## Optimised

```
nums.sort()
for i in range(n - 2):
    if nums[i] > 0: break
    if i > 0 and nums[i] == nums[i - 1]: continue
    l, r = i + 1, n - 1
    while l < r:
        s = nums[i] + nums[l] + nums[r]
        if s < 0: l += 1
        elif s > 0: r -= 1
        else:
            add [nums[i], nums[l], nums[r]]
            l += 1; r -= 1
            while l < r and nums[l] == nums[l - 1]: l += 1
```

## Invariant

- Sorted, so equal values sit next to each other. Skipping a value equal to the one before means each triplet is found once.
- If `nums[i] > 0`, every number after it is positive too, so stop.

## Time and space

- Time O(n²). The sort is O(n log n) and doesn't change that.
- Space O(n) for Python's sort, O(1) apart from that.

## Variation

Q: What if you need the triplet sum closest to a target instead?

A: Same loop, track the sum with the smallest `abs(s - target)`. No duplicate skipping needed. That's 16 3Sum Closest.
